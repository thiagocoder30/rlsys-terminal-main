# D000.6 — Decision Engine

**Programa:** DEV000.4 — Decision Intelligence Core

**Status:** Architecture Approved

**Versão:** 1.0

---

# Objetivo

O Decision Engine será o novo núcleo decisório do RL.SYS.

Sua responsabilidade é consolidar todas as análises produzidas pelos módulos especializados e transformá-las em uma única recomendação institucional.

O Decision Engine não executa estratégias.

Ele decide:

- se existe oportunidade;
- qual estratégia possui maior expectativa;
- qual o nível de confiança;
- qual exposição financeira é aceitável;
- por qual motivo a decisão foi tomada.

Toda a lógica decisória passa exclusivamente por este componente.

---

# Princípio Arquitetural

Nenhum componente do sistema pode selecionar estratégias diretamente.

É proibido que:

- HUD
- Hooks React
- Componentes
- Estratégias
- Painéis
- Risk Manager

escolham estratégias.

Todos consultam exclusivamente:

DecisionEngine.evaluate()

```
Timeline

```

---

# Entrada

O Decision Engine recebe um único objeto.

```
DecisionContext
```

O contexto contém todas as informações necessárias.

Exemplo:

- Timeline
- Cadeia de Markov
- Entropia
- Frequências
- Estado da banca
- Drawdown
- VIX
- Burn-In
- Cooldown
- Performance das estratégias
- Configuração institucional

Nenhuma informação deve ser buscada internamente.

Toda informação deve chegar pelo contexto.

---

# Saída

O retorno será um único objeto.

```
DecisionResult
```

Exemplo conceitual:

```
approved

strategy

confidence

stake

reason

analysis
```

Esse objeto será utilizado pelo HUD.

---

# Responsabilidades

O Decision Engine possui exatamente seis responsabilidades.

## 1. Receber o contexto

Nenhuma consulta externa.

Nenhum estado interno.

Toda decisão deve ser determinística.

---

## 2. Executar os analisadores

Executa:

- EntropyAnalyzer
- MarkovAnalyzer
- FrequencyAnalyzer
- SectorAnalyzer

Os módulos nunca conversam entre si.

Todos retornam métricas independentes.

---

## 3. Solicitar pontuação

Após receber todas as métricas:

```
StrategyScoreEngine.evaluate(...)
```

retorna uma lista ordenada.

Exemplo:

```
Fusion

score 91

confidence 82%
```

```
Voisins

score 87

confidence 74%
```

```
Tiers

score 79

confidence 63%
```

---

## 4. Aplicar camada de risco

Antes de aprovar qualquer entrada:

ExposureController

↓

DrawdownGuard

↓

Kelly Controller

↓

Stake Validation

Caso qualquer etapa falhe:

```
approved = false
```

---

## 5. Construir explicação

Toda decisão deve ser explicável.

Exemplo:

```
Fusion selecionada

Markov favorável

Entropia moderada

Compatibilidade setorial elevada

Confiança 82%

Stake reduzida por exposição
```

Nunca retornar apenas um número.

Sempre retornar justificativa.

---

## 6. Produzir DecisionResult

Última responsabilidade.

O Decision Engine nunca altera estados.

Ele apenas retorna uma decisão.

---

# Filosofia

O Decision Engine funciona como um Investment Committee.

Os módulos apresentam evidências.

O Engine delibera.

A estratégia não "ganha".

Ela é aprovada pelo comitê.

---

# Benefícios

Arquitetura desacoplada.

Alta testabilidade.

Baixo acoplamento.

Alta explicabilidade.

Fácil evolução.

Novos analisadores podem ser adicionados sem alterar o núcleo.

O Decision Engine permanece pequeno enquanto a inteligência cresce ao seu redor.
