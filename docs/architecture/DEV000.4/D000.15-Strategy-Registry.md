DEV000.4 — Decision Intelligence Core

D000.15 — Strategy Registry Specification

1. Objetivo

O Strategy Registry é o componente responsável pelo gerenciamento centralizado das estratégias disponíveis no Decision Intelligence Core.

Sua responsabilidade é fornecer uma camada de descoberta, registro, validação e acesso às estratégias sem acoplar o Decision Engine às implementações concretas.

O Registry atua como um catálogo operacional de estratégias, permitindo que o sistema evolua com novas estratégias sem alterar o núcleo de decisão.

---

2. Motivação Arquitetural

Antes do Decision Intelligence Core, a seleção de estratégias estava diretamente ligada ao fluxo operacional do hook "useTacticalEngine".

Esse modelo gerava:

- acoplamento entre decisão e implementação;
- dificuldade para adicionar novas estratégias;
- impossibilidade de comparar estratégias de forma uniforme;
- mistura entre regra estratégica e decisão operacional.

O Strategy Registry resolve esse problema criando uma fronteira clara:

Strategy Implementation
          |
          v
   Strategy Registry
          |
          v
   Decision Engine

A estratégia deixa de controlar a decisão.

Ela passa apenas informações para o sistema de decisão.

---

3. Responsabilidades

O Strategy Registry possui as seguintes responsabilidades:

3.1 Registro

Permitir que estratégias sejam adicionadas ao sistema.

Exemplo:

StrategyRegistry.register(strategy)

---

3.2 Descoberta

Permitir que o Decision Engine conheça as estratégias disponíveis.

Exemplo:

StrategyRegistry.list()

Retorno esperado:

[
  "TRIPLICACAO",
  "FUSION_REDUZIDA"
]

---

3.3 Recuperação

Permitir acesso a uma estratégia específica.

Exemplo:

StrategyRegistry.get(name)

---

3.4 Execução controlada

Permitir execução padronizada da análise estratégica.

Exemplo:

StrategyRegistry.execute(
    strategyName,
    context
)

---

4. Posição na Arquitetura

O Strategy Registry pertence à camada de estratégias.

Arquitetura:

                Decision Engine
                      |
                      |
              Strategy Registry
                      |
        +-------------+-------------+
        |             |             |
   Strategy A    Strategy B    Strategy C

O Decision Engine nunca importa estratégias diretamente.

---

5. Contrato de Estratégia

Toda estratégia deve implementar um contrato comum.

Interface conceitual:

interface Strategy {

    name: string;

    analyze(
        context: DecisionContext
    ): StrategyResult;


    confidence(
        context: DecisionContext
    ): number;


    explain(
        context: DecisionContext
    ): string;

}

---

6. Strategy Result

Toda estratégia deve retornar uma avaliação padronizada.

Modelo:

interface StrategyResult {

    score: number;

    confidence: number;

    metadata?: Record<string, unknown>;

}

O resultado não executa uma decisão.

Ele apenas fornece evidências.

---

7. Princípio Fundamental

O Registry não decide.

Ele apenas disponibiliza estratégias.

Fluxo correto:

Strategy
    |
    v
Strategy Registry
    |
    v
Strategy Score Engine
    |
    v
Decision Engine
    |
    v
Decision Result

---

8. Integração com Strategy Score Engine

O Registry fornece as estratégias disponíveis.

O Strategy Score Engine avalia:

- performance histórica;
- confiança;
- compatibilidade com features;
- contexto atual.

Exemplo:

Registry

Strategy A
Strategy B
Strategy C


Score Engine

A = 72 pontos
B = 88 pontos
C = 61 pontos


Decision Engine

Seleciona B

---

9. Regras de Isolamento

O Strategy Registry NÃO deve:

- controlar bankroll;
- calcular stake;
- bloquear operações;
- acessar HUD;
- alterar histórico de spins;
- executar apostas;
- substituir o Decision Engine.

---

10. Integração com Estratégias Existentes

As estratégias atuais devem permanecer intactas.

O Registry deve atuar como uma camada adaptadora.

Não realizar:

Modificar estratégia existente
        |
        X

Realizar:

Estratégia existente
        |
        v
Adapter
        |
        v
Strategy Registry

---

11. Evolução Futura

O Strategy Registry permite futuras capacidades:

Dynamic Loading

Adicionar estratégias sem alterar o núcleo.

---

Strategy Versioning

Exemplo:

TRIPLICACAO_v1
TRIPLICACAO_v2

---

Strategy Lifecycle

Estados possíveis:

REGISTERED
ACTIVE
SHADOW
DISABLED
DEPRECATED

---

12. Critérios Arquiteturais

O componente deve garantir:

- baixo acoplamento;
- alta extensibilidade;
- contratos estáveis;
- compatibilidade com TypeScript strict;
- isolamento das estratégias;
- integração limpa com Decision Engine.

---

13. Resultado Esperado

Após implementação do Strategy Registry:

O Decision Intelligence Core possuirá uma camada estratégica independente.

O sistema poderá:

- cadastrar novas estratégias;
- comparar estratégias;
- evoluir modelos;
- realizar testes A/B;
- executar análise supervisionada;

sem modificar o núcleo de decisão.
