DEV000.4 — Decision Intelligence Core

D000.30 — Operational Observability Specification

1. Objetivo

Este documento define a arquitetura de observabilidade operacional do Decision Intelligence Core.

A observabilidade tem como objetivo permitir que todas as decisões produzidas pelo sistema sejam:

- rastreáveis;
- explicáveis;
- auditáveis;
- mensuráveis;
- reproduzíveis.

O Decision Intelligence Core não deve apenas produzir uma decisão, mas também fornecer evidências suficientes para compreender:

- quais dados foram utilizados;
- quais features influenciaram a decisão;
- quais estratégias foram avaliadas;
- quais restrições de risco foram aplicadas;
- por que uma decisão foi aprovada ou rejeitada.

---

2. Princípio Arquitetural

O princípio central é:

«Toda decisão deve possuir uma trilha de evidência.»

O sistema deve evitar decisões opacas.

Uma decisão sem contexto analítico não é considerada uma decisão institucional.

---

3. Camada de Observabilidade

A observabilidade será organizada em quatro níveis.

3.1 Decision Trace

Responsável pelo registro completo de cada avaliação.

Exemplo:

DecisionTrace
|
├── timestamp
├── input context
├── feature analysis
├── strategy scores
├── risk validation
└── final result

---

3.2 Feature Telemetry

Responsável pelo monitoramento dos analisadores.

Exemplos:

Entropy Analyzer:

entropy:
4.82

classification:
ACTIVE

Markov Analyzer:

transition_confidence:
0.71

Frequency Analyzer:

hot_numbers:
[7,17,32]

Sector Analyzer:

sector_alignment:
true

---

3.3 Strategy Telemetry

Responsável por registrar o comportamento das estratégias.

Informações monitoradas:

- score calculado;
- confiança;
- histórico;
- performance;
- taxa de aprovação;
- taxa de rejeição.

Modelo:

StrategyTelemetry

strategy:
Fusion

score:
87

confidence:
0.82

status:
SELECTED

---

3.4 Risk Telemetry

Responsável pelo acompanhamento das decisões bloqueadas.

Exemplos:

RiskEvent

type:
DRAWDOWN_BLOCK

reason:
Loss acceleration detected

ou:

RiskEvent

type:
EXPOSURE_LIMIT

reason:
Stake above allowed exposure

---

4. Decision Audit Record

Toda decisão deve gerar um registro padronizado.

Modelo:

DecisionAuditRecord

id

timestamp

contextSnapshot

featureSnapshot

strategyEvaluation

riskEvaluation

decisionResult

---

5. Integração com Decision Engine

O Decision Engine não deve implementar armazenamento de logs diretamente.

Responsabilidade:

DecisionEngine
        |
        v
DecisionTraceEmitter
        |
        v
Observability Layer

Separação:

- Engine decide;
- Observability registra.

---

6. Métricas Operacionais

O sistema deve acompanhar:

Decisão

- quantidade de avaliações;
- decisões aprovadas;
- decisões bloqueadas;
- confiança média.

Estratégias

- estratégia mais selecionada;
- estratégia com maior score médio;
- degradação de performance.

Risco

- bloqueios por exposição;
- bloqueios por drawdown;
- períodos de instabilidade.

---

7. Objetivo Futuro

A camada de observabilidade permitirá:

- análise posterior das decisões;
- comparação entre estratégias;
- identificação de degradação;
- calibração dos modelos;
- explicabilidade operacional.

---

8. Restrições

Esta especificação não altera:

- HUD;
- bankroll management;
- stop loss;
- take profit;
- ingestão de spins;
- definição das estratégias existentes.

A observabilidade atua somente como camada transversal.

---

9. Critério de Aceitação

A implementação será considerada válida quando:

- toda decisão possuir trace associado;
- features produzirem métricas auditáveis;
- estratégias possuírem histórico de avaliação;
- bloqueios de risco forem explicáveis;
- nenhum componente operacional existente for quebrado.
