D000.23 — Plano de Testes

DEV000.4 — Decision Intelligence Core

Documento: D000.23
Módulo: Quality Assurance & Validation Strategy
Status: Architecture Specification
Versão: 1.0

---

1. Objetivo

Este documento define a estratégia oficial de testes para validar a implementação da DEV000.4 — Decision Intelligence Core.

O objetivo é garantir que o novo núcleo decisório seja:

- correto;
- previsível;
- testável;
- explicável;
- seguro;
- compatível com o runtime existente.

A estratégia de testes deve validar tanto componentes isolados quanto o fluxo completo de decisão.

---

2. Princípios de Testabilidade

A arquitetura DEV000.4 deve seguir:

2.1 Testes independentes

Cada componente deve possuir testes próprios.

Exemplo:

EntropyAnalyzer

não depende de:

DecisionEngine
HUD
useTacticalEngine

---

2.2 Determinismo

Dado o mesmo:

- contexto;
- histórico;
- estado;

o Decision Engine deve produzir o mesmo resultado.

---

2.3 Explicabilidade

Toda decisão aprovada deve possuir:

- estratégia escolhida;
- confiança;
- motivo;
- dados utilizados.

---

3. Pirâmide de Testes

A arquitetura utilizará três níveis:

                 E2E

        Integration Tests

      Unit Tests

---

4. Testes Unitários

Objetivo

Validar cada componente individualmente.

Local:

tests/decision/

---

5. Testes de Contracts

DecisionContext

Arquivo:

decision-context.test.ts

Validar:

- criação do contexto;
- campos obrigatórios;
- compatibilidade de tipos.

Exemplo:

DecisionContext
{
 timeline,
 bankroll,
 vix,
 markovMatrix
}

---

DecisionResult

Validar:

- resultado aprovado;
- resultado bloqueado;
- explicação presente.

---

6. Testes da Feature Layer

6.1 Entropy Analyzer

Arquivo:

entropy.test.ts

Validar:

- cálculo de entropia;
- classificação de regime;
- comportamento com histórico vazio.

Casos:

Baixa entropia

Alta concentração

Distribuição uniforme

---

6.2 Markov Analyzer

Arquivo:

markov.test.ts

Validar:

- cálculo de transição;
- confiança;
- ausência de dados.

Casos:

Transição forte

Transição fraca

Matriz vazia

---

6.3 Frequency Analyzer

Arquivo:

frequency.test.ts

Validar:

- números mais frequentes;
- números menos frequentes;
- histórico curto.

---

6.4 Sector Analyzer

Arquivo:

sector.test.ts

Validar:

- compatibilidade setorial;
- presença de números;
- ausência de setor.

---

7. Testes da Strategy Layer

7.1 Strategy Score Engine

Arquivo:

scoring.test.ts

Validar:

- ordenação das estratégias;
- cálculo de score;
- impacto dos indicadores.

Exemplo:

Entrada:

Strategy A

score: 50


Strategy B

score: 80

Resultado esperado:

Strategy B primeiro

---

7.2 Strategy Registry

Arquivo:

registry.test.ts

Validar:

- registro;
- consulta;
- execução;
- tratamento de estratégia inexistente.

---

8. Testes da Risk Layer

8.1 Exposure Controller

Arquivo:

exposure.test.ts

Validar:

- limite máximo de exposição;
- bloqueio acima do limite.

Exemplo:

Bankroll: 1000

Limite: 5%

Stake permitido:
<=50

---

8.2 Drawdown Guard

Arquivo:

drawdown.test.ts

Validar:

- sequência negativa;
- bloqueio preventivo;
- recuperação.

---

9. Testes do Decision Engine

Arquivo:

decision-engine.test.ts

Este é o teste principal da arquitetura.

Validar:

DecisionContext

        |

DecisionEngine.evaluate()

        |

DecisionResult

---

Cenários obrigatórios

Cenário 1 — Decisão aprovada

Entrada:

- contexto válido;
- risco aceitável;
- estratégia disponível.

Esperado:

approved = true

---

Cenário 2 — Bloqueio por risco

Entrada:

- exposição acima do limite.

Esperado:

approved = false

---

Cenário 3 — Histórico insuficiente

Entrada:

- burn-in incompleto.

Esperado:

approved = false

---

10. Testes de Integração

Objetivo:

Validar comunicação entre camadas.

Fluxo:

Context

 |

Feature Layer

 |

Strategy Score

 |

Risk Layer

 |

Decision Result

---

Arquivo:

decision-pipeline.integration.test.ts

Validar:

- dados passando corretamente;
- ausência de perda de informação;
- explicação preservada.

---

11. Testes de Compatibilidade Runtime

Após integração com:

src/core/useTacticalEngine.ts

validar:

- HUD permanece funcionando;
- estados antigos continuam existentes;
- ingestão continua funcionando;
- bankroll permanece correto.

---

12. Testes de Regressão

Obrigatórios:

Executar:

npm test

e:

npm run build

Critério:

Nenhuma funcionalidade existente pode quebrar.

---

13. Testes de Auditoria

Cada decisão deve permitir reconstrução.

Exemplo:

Entrada:

Timeline X

Context Y

Saída:

Strategy escolhida

Confidence

Features utilizadas

Risk decision

---

14. Critérios de Aprovação

A DEV000.4 será considerada validada quando:

Código

- todos testes unitários passam;
- testes integração passam;
- build passa.

Arquitetura

- Decision Engine isolado;
- Features independentes;
- Risk Layer funcionando.

Operação

- HUD intacto;
- runtime preservado;
- decisões explicáveis.

---

15. Resultado Esperado

Após a implementação dos testes:

Decision Intelligence Core

        |

Validado por testes automatizados

        |

Seguro para integração operacional

A camada decisória passa a possuir garantia técnica antes de assumir autoridade sobre decisões do sistema.
