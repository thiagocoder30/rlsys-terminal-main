# D000.7 — Decision Context

**Programa:** DEV000.4 — Decision Intelligence Core

**Status:** Architecture Approved

**Versão:** 1.0

---

# Objetivo

O DecisionContext é o contrato oficial de entrada do Decision Engine.

Nenhum componente interno do motor decisório poderá acessar diretamente estados do React, LocalStorage, Hooks, HUD ou qualquer outra estrutura da aplicação.

Todo o conhecimento necessário para uma decisão deverá estar encapsulado em um único objeto imutável.

Este documento define esse contrato.

---

# Princípios

O DecisionContext deve obedecer aos seguintes princípios:

- Imutável durante todo o processo decisório.
- Independente do framework (React, Vue, Angular, etc.).
- Independente da interface gráfica.
- Independente do provedor da roleta.
- Serializável.
- Testável.
- Reutilizável em simulações e backtests.

---

# Fluxo Arquitetural

```
React Hook

↓

Coleta dos estados

↓

Construção do DecisionContext

↓

DecisionEngine.evaluate(context)

↓

DecisionResult

↓

HUD
```

O Decision Engine nunca deverá acessar diretamente estados da aplicação.

---

# Estrutura Geral

O DecisionContext será composto por oito blocos de informações.

```
DecisionContext

├── Timeline
├── Mesa
├── Bankroll
├── Mercado
├── Performance
├── Segurança
├── Configuração
└── Metadados
```

Cada bloco possui uma responsabilidade única.

---

# Timeline

Representa o histórico recente da mesa.

Exemplo de informações:

- últimos giros;
- quantidade de amostras;
- repetições;
- distribuição numérica.

Este bloco é utilizado por:

- EntropyAnalyzer
- FrequencyAnalyzer
- MarkovAnalyzer

---

# Mesa

Descreve o estado operacional da mesa.

Exemplos:

- Burn-In restante;
- Cooldown;
- número do último giro;
- VIX;
- mesa aprovada ou rejeitada pelo Pre-Flight;
- índice de estabilidade.

Esse bloco representa a condição atual da mesa.

---

# Bankroll

Contém exclusivamente informações financeiras.

Exemplos:

- banca atual;
- banca inicial;
- banca máxima da sessão;
- lucro acumulado;
- drawdown;
- Stop Loss;
- Take Profit;
- limite máximo por entrada.

Esse bloco será utilizado apenas pela camada de risco.

---

# Mercado

Representa os indicadores estatísticos produzidos pelos analisadores.

Exemplos:

- matriz de Markov;
- entropia;
- frequência;
- setores quentes;
- setores frios;
- concentração;
- dispersão.

Essas informações são produzidas pela Feature Layer.

---

# Performance

Contém o histórico institucional das estratégias.

Cada estratégia possuirá indicadores próprios.

Exemplos:

- peso atual;
- confiança;
- PnL acumulado;
- média móvel;
- Z-Score;
- taxa de acerto;
- quantidade de ativações.

Nenhuma estratégia poderá consultar LocalStorage diretamente.

Toda informação deverá chegar por este bloco.

---

# Segurança

Informações utilizadas pela Risk Layer.

Exemplos:

- velocidade de drawdown;
- exposição atual;
- sequência negativa;
- sequência positiva;
- risco permitido;
- trava institucional.

Este bloco determina se uma operação pode ser aprovada.

---

# Configuração

Representa parâmetros institucionais.

Exemplos:

- provedor;
- chip mínimo;
- Kelly máximo;
- exposição máxima;
- limites operacionais;
- estratégias habilitadas;
- estratégias bloqueadas.

Nenhum módulo deverá consultar configurações diretamente.

---

# Metadados

Informações auxiliares para auditoria.

Exemplos:

- horário;
- versão do algoritmo;
- identificador da sessão;
- versão do motor;
- identificador da análise.

Este bloco facilita rastreabilidade e auditoria.

---

# Construção

O DecisionContext deverá ser criado exclusivamente por um Builder.

Fluxo:

```
React

↓

DecisionContextBuilder

↓

DecisionContext

↓

DecisionEngine
```

Isso evita que diferentes partes do sistema montem contextos inconsistentes.

---

# Benefícios

O uso do DecisionContext proporciona:

- desacoplamento total;
- testes determinísticos;
- simulações reproduzíveis;
- facilidade de evolução;
- isolamento do motor decisório;
- independência da interface gráfica.

---

# Regra Institucional

O Decision Engine jamais deverá acessar diretamente:

- Hooks React;
- useState;
- LocalStorage;
- componentes;
- HUD;
- providers;
- APIs.

Toda informação deverá estar presente no DecisionContext.

Essa regra é obrigatória para preservar o isolamento arquitetural.
