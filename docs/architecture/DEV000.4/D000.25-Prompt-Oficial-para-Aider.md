---

1. Objetivo

Este documento define o prompt oficial que será utilizado pelo Aider para implementar a arquitetura DEV000.4 — Decision Intelligence Core.

O Aider não possui responsabilidade arquitetural.

Sua função é exclusivamente:

- implementar código conforme especificação;
- respeitar contratos definidos;
- criar arquivos solicitados;
- executar testes;
- corrigir erros de compilação;
- não alterar componentes fora do escopo.

Toda decisão arquitetural permanece sob responsabilidade deste documento.

---

2. Contexto Arquitetural

O RL.SYS Core possui atualmente:

- ingestão de spins;
- gerenciamento de bankroll;
- HUD operacional;
- estratégias existentes;
- métricas estatísticas;
- controle de sessão.

A DEV000.4 introduz uma nova camada:

Decision Intelligence Core

Responsável por transformar dados analíticos em decisões estruturadas.

A nova arquitetura deve separar:

Strategy
    |
    v
Strategy Analysis

    |
    v

Decision Intelligence Core

    |
    v

Decision Result

    |
    v

Execution / HUD

O Aider NÃO DEVE:

5. Decision Engine

Criar um ponto único de decisão:

DecisionEngine.evaluate(context)

Responsabilidades:

- receber DecisionContext;
- executar pipeline analítico;
- avaliar estratégias;
- aplicar regras de risco;
- retornar DecisionResult.

O DecisionEngine NÃO deve executar apostas.

Ele apenas produz uma decisão.

---

6. Decision Context

O contexto deve representar todas as informações necessárias:

Exemplo:

interface DecisionContext {

timeline: number[];

bankroll: number;

vix: number;

markovMatrix: number[];

strategyPerformance: StrategyPerformance[];

cooldown: number;

burnIn: number;

}

Novos campos somente podem ser adicionados se forem necessários ao domínio.

---

7. Decision Result

O resultado deve ser determinístico e auditável.

Formato esperado:

interface DecisionResult {

approved:boolean;

strategy:string | null;

confidence:number;

stake:number;

reason:string;

analysis:Record<string, unknown>;

}

---

8. Feature Layer

Implementar analisadores independentes:

Entropy Analyzer

Responsável por:

- medir entropia;
- classificar regime estatístico.

---

Markov Analyzer

Responsável por:

- analisar transições;
- calcular confiança probabilística.

---

Frequency Analyzer

Responsável por:

- identificar frequência;
- detectar números quentes e frios.

---

Sector Analyzer

Responsável por:

- avaliar setores;
- identificar compatibilidade estratégica.

---

9. Strategy Score Engine

Criar camada responsável por ranking.

Entrada:

StrategyPerformance[]

Saída:

StrategyScore[]

Critérios:

- performance histórica;
- confiança;
- compatibilidade estatística;
- contexto atual.

A camada não cria estratégias.

Apenas avalia.

---

10. Strategy Registry

Criar registro centralizado.

Responsabilidades:

- armazenar estratégias;
- permitir descoberta;
- executar análise.

Não migrar estratégias antigas automaticamente.

A compatibilidade deve ser progressiva.

---

11. Risk Layer

Criar proteção independente.

Componentes:

Risk Layer

    |
    +-- Exposure Controller

    |
    +-- Drawdown Guard

---

12. Exposure Controller

Responsável por limitar exposição.

Regra inicial:

stake <= 5% bankroll

Nenhuma decisão pode ultrapassar esse limite.

---

13. Drawdown Guard

Responsável por bloquear decisões em cenários perigosos.

Avaliar:

- sequência negativa;
- aceleração de perdas;
- deterioração operacional.

---
