# ADR-040.3 — Startup Wizard Runtime Ownership Architecture (SWROA)

**Status:** ACCEPTED

**Data:** 2026-07-29

**Sprint:** Hotfix Arquitetural

**Autores:** OpenAI Architecture + RL.SYS CORE Team

---

# 1. CONTEXTO

Durante a validação funcional das ADR-040, ADR-040.1 e ADR-040.2 foi identificado que, embora toda a infraestrutura de configuração operacional tenha sido implementada, o fluxo de inicialização da aplicação não está sendo governado pelo Session Startup Wizard.

Na implementação atual observou-se que:

- o HUD Operacional é renderizado imediatamente após o carregamento do frontend;
- o Startup Wizard funciona apenas como um componente opcional;
- as alterações realizadas durante o Wizard não controlam efetivamente a criação da sessão operacional;
- o valor da banca configurado não é propagado para o SessionControlEngine;
- a troca de provedor (Pragmatic/Evolution) não altera imediatamente o comportamento operacional esperado;
- o botão "Continuar" permite prosseguir mesmo sem todas as etapas obrigatórias concluídas;
- após reiniciar o aplicativo o Wizard não é executado novamente quando deveria.

Esses comportamentos violam diretamente os princípios definidos nas ADRs anteriores.

---

# 2. PROBLEMA

O problema não está na implementação dos componentes.

O problema está na governança do ciclo de vida da aplicação.

Atualmente não existe um único responsável por decidir qual interface deve ser apresentada ao operador.

Na prática existem dois pontos de entrada concorrentes:

- OperatorConsole
- SessionStartupWizard

Essa arquitetura permite estados inconsistentes e quebra a previsibilidade operacional.

---

# 3. DECISÃO

A partir desta ADR o Session Startup Wizard passa oficialmente a ser o único proprietário ("Owner") do fluxo de inicialização do RL.SYS CORE.

Nenhum componente visual poderá iniciar diretamente uma sessão operacional.

Toda entrada do operador deverá obrigatoriamente passar pelo Startup Wizard.

---

# 4. PRINCÍPIO ARQUITETURAL

Estabelece-se oficialmente o conceito de:

Startup Runtime Ownership

A responsabilidade pelo ciclo de vida inicial pertence exclusivamente ao SessionStartupWizard.

Nenhum outro componente poderá assumir essa responsabilidade.

---

---

# 6. APPLICATION BOOTSTRAP

Criar oficialmente um componente responsável exclusivamente pelo bootstrap institucional.

Responsabilidades:

- carregar configurações;
- validar configurações;
- consultar estado da sessão;
- decidir qual tela será aberta;
- impedir renderização prematura do HUD.

Nenhum cálculo operacional deverá ocorrer nessa camada.

---

# 7. RUNTIME CONFIGURATION STATE

Criar um único estado institucional responsável por representar toda a configuração operacional.

Esse estado torna-se a única fonte oficial de verdade para o frontend.

Todos os componentes deverão consumir exclusivamente esse estado.

Não será permitido estado duplicado.

---

# 8. SESSION STARTUP WIZARD

O Wizard passa a possuir autoridade exclusiva para:

- seleção do provedor;
- configuração da banca;
- idioma;
- tema;
- sincronização;
- warmup;
- validação;
- criação da sessão.

Nenhum desses processos poderá ser iniciado pelo HUD.

---

# 9. SESSION CONTROL

A criação da sessão deverá ocorrer exclusivamente através da chamada:

SessionControlEngine.startSession()

Essa chamada somente poderá ocorrer quando o Startup Wizard concluir todas as etapas obrigatórias.

---

# 10. OPERATIONAL HUD

O HUD deixa oficialmente de possuir qualquer responsabilidade de inicialização.

Sua única responsabilidade passa a ser:

observar.

O HUD apenas renderiza o estado recebido do backend.

Nunca poderá:

- criar sessão;
- alterar banca;
- alterar provedor;
- alterar idioma;
- alterar tema.

---

# 11. BOTÃO CONTINUAR

O botão "Continuar" deverá permanecer permanentemente desabilitado enquanto qualquer etapa obrigatória estiver pendente.

Somente poderá ser habilitado quando:

✓ Provedor selecionado

✓ Banca válida

✓ Idioma definido

✓ Tema definido

✓ Configuração validada

Somente então:

READY

↓

Continuar habilitado

---

# 12. PROPAGAÇÃO DE CONFIGURAÇÃO

Ao concluir o Wizard deverá ocorrer obrigatoriamente:

ConfigurationEngine

↓

SessionControlEngine

↓

BankrollManager

↓

ProviderConfiguration

↓

OperationalConfiguration

↓

RuntimeConfigurationState

↓

HUD

A atualização deverá ocorrer imediatamente.

Não será permitido reload manual para refletir mudanças.

---

# 13. NOVA SESSÃO

Quando existir configuração válida o sistema deverá perguntar ao operador:

Deseja continuar utilizando a configuração atual?

[ Continuar ]

[ Nova Sessão ]

Selecionando "Nova Sessão":

- limpar estado transitório;
- reiniciar Startup Wizard;
- preservar apenas configurações persistentes quando aplicável;
- iniciar novo fluxo operacional.

---

# 14. CONTINUAR SESSÃO

Selecionando "Continuar":

ApplicationBootstrap

↓

RuntimeConfigurationState

↓

SessionControlEngine

↓

Operational HUD

Nenhuma etapa do Wizard será reexecutada.

---

# 15. RESTRIÇÕES

Permanece proibido:

- lógica quantitativa no frontend;
- criação de sessão pelo React;
- múltiplos pontos de bootstrap;
- múltiplas fontes de configuração;
- estados paralelos.

---

# 16. IMPACTO ARQUITETURAL

Esta ADR altera exclusivamente o fluxo de inicialização da aplicação.

Nenhum motor quantitativo poderá sofrer alterações.

Permanecem intactos:

- IntelligenceRuntime;
- QuantitativeEnginePipeline;
- Recommendation Engine;
- Session Audit;
- Session Intelligence;
- Institutional AI;
- Strategy Evolution Governance;
- Decision Ledger.

---

# 17. VALIDAÇÃO OBRIGATÓRIA

A implementação somente poderá ser homologada quando todos os itens abaixo forem comprovados.

Primeira execução:

✓ Wizard abre automaticamente.

Sem preencher todos os campos:

✓ Botão Continuar permanece desabilitado.

Selecionando:

Pragmatic

↓

Ficha mínima atualizada imediatamente.

Selecionando:

Evolution

↓

Ficha mínima atualizada imediatamente.

Alterando banca:

↓

HUD atualizado imediatamente após criação da sessão.

Reiniciando aplicação:

↓

Wizard somente será ignorado quando existir configuração válida e o operador optar por continuar.

Selecionando:

Nova Sessão

↓

Wizard reiniciado integralmente.

HUD nunca poderá ser exibido antes da conclusão do Wizard.

---

# 18. CHECKLIST INSTITUCIONAL

✓ Startup Wizard torna-se único proprietário do bootstrap.

✓ ApplicationBootstrap torna-se responsável pelo fluxo inicial.

✓ RuntimeConfigurationState torna-se única fonte de verdade.

✓ SessionControlEngine somente inicia após validação completa.

✓ HUD torna-se exclusivamente observador.

✓ Nenhum estado duplicado permanece.

✓ Nenhuma lógica operacional permanece no frontend.

✓ Frontend continua Thin Client.

✓ IntelligenceRuntime permanece Single Point of Execution.

✓ PaperOnly permanece true.

✓ ProductionMoneyAllowed permanece false.

✓ DecisionLedger permanece Append Only.

---

# 19. CONCLUSÃO

Esta ADR elimina definitivamente a existência de múltiplos pontos de entrada do sistema e institucionaliza o Session Startup Wizard como proprietário exclusivo do ciclo de vida inicial do RL.SYS CORE.

Essa decisão encerra a fase de estabilização arquitetural do bootstrap e estabelece uma base sólida para a FASE 2 — Persistência, garantindo previsibilidade operacional, sincronização consistente de estados e uma experiência de uso adequada tanto em ambiente desktop quanto em dispositivos móveis.
